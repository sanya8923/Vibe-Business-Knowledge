## Зачем это

По лентам расходятся подборки «must-have для Claude Code» — обычно это ссылка и восторженное описание. Мы взяли шесть таких репозиториев и проверили каждый **запуском**, а не чтением README. Результат оказался резче ожидаемого: **два из шести не существуют по тем ссылкам, по которым их советуют**, а один — официальный плагин Anthropic — установлен, но не работает и не сообщает об этом.

Ниже — что реально проверено, чем именно, и что из этого стоит ставить.

## 1. Две ссылки ведут в никуда

**`coleam00/claude-memory`** — GitHub API отдаёт 404. Поиск по владельцу даёт единственное совпадение: **`coleam00/claude-memory-compiler`** (1274★, Python). Это система, которая хуками ловит конец сессии, через Claude Agent SDK вытаскивает из разговора решения и уроки в дневной лог, а потом компилирует логи в concept-статьи с перекрёстными ссылками. Ретрив без RAG — структурированный `index.md` вместо векторов (идея Карпатого: на 50–500 статьях LLM по индексу бьёт косинусную близость).

**`hmarr/headroom`** — 404, и у владельца `hmarr` **ноль** репозиториев с таким именем. При этом под именем «headroom» вокруг Claude Code живут **пять разных проектов**:

| Проект | Что делает |
|---|---|
| `henchmarketing-rgb/headroom` | бар заполнения контекста в statusline |
| `patwalls/headroom` | menu-bar: 5-часовое окно, недельная квота, стоимость (macOS) |
| `allandecastro/headroom` | квоты Claude Code + Copilot, Tauri (macOS) |
| `gglucass/headroom-desktop` | трей-приложение снижения затрат (macOS) |
| `headroomlabs-ai/headroom` | компрессия контекста: библиотека + прокси + MCP (66k★) |

**Практический вывод:** прежде чем ставить «то самое» из подборки, проверьте, что репозиторий вообще существует по названной ссылке. В двух случаях из шести — не существовал.

## 2. Официальный плагин Anthropic, который молча не работает

Самая поучительная находка. В маркетплейсе `anthropics/claude-code` есть плагин **`hookify`** — «создавай хуки из markdown-правил». Мы поставили его глобально и **прогнали хуки вживую до включения в работу**. Он не работает, причём по двум независимым причинам.

**Причина 1 — окружение (Windows).** Все четыре его хука (PreToolUse, PostToolUse, Stop, UserPromptSubmit) зашиты на `python3`. На стандартной Windows `python3` в PATH — это **App Execution Alias Microsoft Store** (`.../WindowsApps/python3.exe` → `AppInstallerPythonRedirector.exe`), который печатает `Python` и завершается с кодом **49**, ничего не исполнив. Запуск ровно так, как вызывает Claude Code:

```
$ echo '{...}' | sh -c "python3 .../hooks/pretooluse.py"
Python
# exit 49
```

Реальный CPython при этом на машине есть — но как `python` и `py`, имени `python3` у него нет.

**Причина 2 — структурная, от ОС не зависит.** Даже настоящим Python:

```
{"systemMessage": "Hookify import error: No module named 'hookify'"}
```

Код делает `from hookify.core.config_loader import …` и кладёт в `sys.path` **родителя** каталога плагина — то есть рассчитывает на структуру `.../plugins/hookify/core/…`. Но Claude Code кэширует плагины в **версионированный** каталог:

```
~/.claude/plugins/cache/<marketplace>/hookify/0.1.0/
```

Родитель — `.../hookify`, внутри него только `0.1.0` — имя, недопустимое как имя Python-модуля. Пакета `hookify` нет ни по одному пути.

**Изоляционный эксперимент** (скопировали те же файлы в каталог с именем `hookify` и запустили тот же хук):

```bash
cp -r ~/.claude/plugins/cache/<mp>/hookify/0.1.0 /tmp/probe/hookify
echo '{"hook_event_name":"PreToolUse","tool_name":"Bash",...}' \
  | CLAUDE_PLUGIN_ROOT=/tmp/probe/hookify python /tmp/probe/hookify/hooks/pretooluse.py
# -> {}   exit 0
```

Те же байты, отличается только имя каталога. Код исправен — сломано предположение о раскладке.

**Почему это опаснее обычного бага.** При ошибке импорта скрипт печатает сообщение и делает `exit 0`. Инструменты продолжают работать, ничего не выглядит сломанным, а **правила пользователя никогда не применяются**. Мы нашли в трекере Anthropic открытый issue [#81448](https://github.com/anthropics/claude-code/issues/81448) — и три закрытых дубля о том же; то есть баг жил месяцами, потому что снаружи он невидим.

**Что из этого следует для любого плагина с хуками:** прогоняйте хуки вживую **до** того, как начнёте на них полагаться. Мы написали для себя маленький гейт, который для каждого установленного плагина находит `hooks.json`, подставляет тестовый stdin и запускает команду ровно так, как это сделает Claude Code, различая три исхода:

- **OK** — команда отработала;
- **FAIL** — ненулевой exit, нет бинаря в PATH, таймаут;
- **SILENT-FAIL** — exit 0, но в выводе `ImportError` / `command not found` / `Traceback` / голое `Python` от Store-заглушки.

Третий класс — тот самый, из-за которого проблема живёт незамеченной.

## 3. Тот же самый капкан — во втором проекте

`henchmarketing-rgb/headroom` (бар контекста в statusline) идея хорошая, но на Windows не заработает, и снова молча:

1. **`python3`** — та же заглушка Store;
2. **путь**: хук ищет транскрипт в `~/.claude/projects/-<cwd>` с ведущим дефисом, а каталоги называются иначе → `sys.exit(0)`, бар вечно показывает `--`;
3. **ключ настройки**: `install.sh` пишет `settings["statusline"]`, а Claude Code читает **`statusLine`** (camelCase) — строка статуса не появится вовсе;
4. **таблица окон контекста** захардкожена под конкретные модели; для незнакомой модели берётся дефолт.

Итого **два проекта из шести** сломаны об одну и ту же вещь — `python3` на Windows, — и оба отказывают тихо.

## 4. Что реально стоит поставить

### `find-skills` (vercel-labs/skills)

Скилл-обёртка над `npx skills` — пакетным менеджером экосистемы скиллов. Проверено живьём: CLI **v1.5.22**, поиск работает **неинтерактивно** (`npx skills find changelog` вернул ранжированный список с числом установок). Установка:

```bash
npx skills add vercel-labs/skills --skill find-skills -g -y -a claude-code
```

Ценно, что скилл несёт собственную дисциплину качества: не рекомендовать по одной выдаче поиска, а сверять число установок (≥1K хорошо, <100 — скепсис), репутацию владельца и звёзды репозитория.

Полезное, чего нет в описании: команда **`npx skills use <package>@<skill>`** генерирует промпт для разового применения скилла **без установки** — можно попробовать чужое, не втаскивая в глобальный контур. Плюс `list`, `remove`, `update -g`, `init`.

### Маркетплейс `anthropics/claude-code`

Репозиторий CLI содержит в корне `.claude-plugin/marketplace.json` — то есть это **официальный маркетплейс из 13 плагинов** Anthropic: `agent-sdk-dev`, `code-review`, `commit-commands`, `feature-dev`, `frontend-design`, `hookify`, `plugin-dev`, `pr-review-toolkit`, `ralph-wiggum`, `security-guidance`, два output-style и миграционный.

```bash
claude plugin marketplace add anthropics/claude-code
claude plugin install plugin-dev@claude-code-plugins --scope user
```

`plugin-dev` (7 экспертных скиллов по разработке плагинов: хуки, MCP, команды, агенты, валидация) — хуков не имеет, в поток выполнения не вмешивается, безопасен. `hookify` — см. раздел 2.

## 5. О чём стоит подумать перед установкой

**`diegosouzapw/OmniRoute`** (MIT, активный, npm-пакет подтверждённо соответствует репозиторию) — гейтвей на 340 провайдеров с авто-фолбэком и компрессией. Технически интересен, но по назначению встаёт **между вашим агентом и провайдером**: через него пойдёт содержимое рабочих файлов и переменные окружения. В списке возможностей заявлен «transparent MITM decrypt» с установкой собственного CA в доверенное хранилище. Для личных экспериментов — вопрос вкуса; для рабочего контура с чужими или коммерческими данными это решение, которое стоит принимать осознанно, а не «поставил из подборки».

**`eyaltoledano/claude-task-master`** — PRD → дерево задач, статусы, зависимости, MCP + CLI. Живой и качественный. Две вещи, о которых стоит знать заранее: он требует API-ключей (отдельный расход), и по собственной документации MCP-режим грузит **36 инструментов ≈ 21 000 токенов** контекста (`standard` — 15 инструментов ≈ 10k, `core` — 7 ≈ 5k). Если трекер уже есть, получите два источника истины.

**`coleam00/claude-memory-compiler`** — самая интересная идея из шести: компиляция дневных логов сессий в concept-статьи с индексом вместо RAG. Ставить целиком стоит, только если у вас **нет** своей системы памяти: иначе это третий слой поверх существующих, плюс Python/uv и фоновые вызовы Agent SDK на каждом завершении сессии.

**`headroomlabs-ai/headroom`** (66k★, Apache-2.0) — компрессия того, что агент читает: выводы инструментов, логи, файлы. Библиотека, прокси и MCP-сервер. Заявляет 47–92% экономии на JSON-тяжёлых нагрузках при сохранённой точности. Важное из их же страницы ограничений: **код почти не сжимается** (намеренно), короткие обмены дают медиану 4.8%, а основной выигрыш — на массивах словарей. Именно поэтому стоит понимать механику: SmartCrusher отдаёт модели **выборку** массива (30% от начала, 15% с конца, 55% по важности, потолок 15 элементов), сохраняя аномалии и ошибки. Для «покажи все записи» это неприемлемо, для «разбери гигантский лог» — то что нужно.

## Что мы забрали себе из этой проверки

1. **Проверять существование по ссылке.** Два из шести не существуют — при том, что их советуют по имени.
2. **Прогонять хуки плагина вживую до включения.** Различать три исхода, а не два: OK / FAIL / **тихий отказ с exit 0**.
3. **На Windows не доверять `python3`.** Это заглушка Store; сторонний код, зашитый на неё, ломается молча. Проверка: `python3 -V` печатает голое `Python` без номера версии.
4. **Не чинить чужой плагин в кэше.** Кэш перетирается при обновлении, а маркетплейс — git-клон: правка исчезнет молча. Либо свой форк-маркетплейс, либо PR в апстрим, либо своя реализация идеи.
