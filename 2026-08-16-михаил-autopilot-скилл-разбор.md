# Autopilot — полное руководство по скиллу

**Что это:** скилл для AI-агентов (Claude Code, Cursor, Codex и 70+ других), который превращает описание задачи словами в собранный проект за один диалог — сам пишет спецификацию, режет работу на таски, строит, проверяет и сдаёт результат.

## 1. Для кого это и когда не надо

**Подходит, когда:**
- вы диктуете, что построить, и хотите получить готовое, а не соучаствовать в процессе;
- вы нетехнический пользователь: не будете читать спецификацию, оценивать дробность тасков и ревьюить код;
- формулировки вида «собери под ключ», «just build it», «не задавай лишних вопросов»;
- вы хотите, чтобы задачу разобрали с вами по вопросам, а собрали без вас (это режим `interview`);
- вы хотите утвердить спецификацию и список тасков, но не гонять конвейер руками (режим `manual`).

**Не подходит, когда** (прямо сказано в коде):
- вы хотите писать код вместе, построчно — работайте с агентом напрямую;
- задача — маленькая правка в одном файле: просто сделайте её;
- идея больше одного проекта и непонятно, куда она едет — сначала определитесь с назначением.

## 2. Установка

Требуется [Node.js](https://nodejs.org) и любой поддерживаемый агент.

### Через терминал

```bash
# интерактивно — установщик спросит, что и куда ставить
npx skills add nick-vels/skills

# одной командой, без вопросов, глобально для Claude Code
npx skills add nick-vels/skills --skill autopilot -a claude-code -g -y
```

| Флаг | Значение |
|---|---|
| `--skill autopilot` | поставить только Autopilot (в репозитории могут быть и другие скиллы) |
| `-a claude-code` | целевой агент: `claude-code`, `cursor`, `codex`, … |
| `-g` | **глобально** — доступен во всех проектах. Без флага встанет только в текущую папку |
| `-y` | не задавать вопросов |

### Через агента (если не хотите открывать терминал)

Вставьте агенту:

```
Установи мне навык Autopilot. Выполни в терминале:
npx skills add nick-vels/skills --skill autopilot -g -y -a <claude-code | cursor | codex>
Если npx не найдётся — дай мне ссылку, где скачать Node.js, и подожди.
Больше ничего не устанавливай.
Когда закончишь — напиши одной строкой, что готово и что надо перезапустить сессию.
```

### Куда лёг и как проверить

```
~/.claude/skills/autopilot/
├── SKILL.md              оркестратор: режимы, порядок фаз, гейты
├── phases/               правила каждой фазы (13 файлов) + dashboard-template.html
└── prompts/craft-review.md   материал для ревьюера
```

Проверка установки: `npx skills list`. В Claude Code скилл обычно виден сразу; в остальных агентах — после перезапуска сессии (скиллы читаются на старте).

**Замечание по целостности:** установщик переписывает файлы в CRLF на Windows — содержимое при этом идентично апстриму (проверено построчным diff, 0 различий). Расхождение md5 с файлами из GitHub — нормально и объясняется только переводом строк.

### Обновление и удаление

```bash
npx skills update autopilot -g       # ОБНОВЛЕНИЕ — только так
npx skills list                      # что установлено
npx skills remove autopilot -g       # удалить
```

⚠️ **Не обновляйте командой `add`** — она для первой установки. Если `update` говорит «уже последняя», а версия старая:

```bash
npx skills remove autopilot -g -y && npx skills add nick-vels/skills --skill autopilot -g -y -a claude-code
```

## 3. Как запускать

```
/autopilot Хочу телеграм-бота, который принимает заявки на ремонт техники
           и складывает их в Google-таблицу
```

Можно и без слэш-команды — скилл сработает по фразам вроде «собери под ключ», «build it for me», «не задавай лишних вопросов».

**Большую задачу пишите в файл.** Название любое (`brief.md`, `идея.txt`, `задача.md`), формат свободный: что за проект, для кого, что должно уметь, что не нравится у конкурентов, ограничения по деньгам и срокам.

```
/autopilot brief.md
/autopilot deep docs/идея.md только без оплаты картой
```

Ваш файл останется нетронутым — его копия ляжет в `.autopilot/`, и именно с ней сверяется результат в конце. Слова, дописанные рядом с путём, идут в ту же задачу.

**Первое, что вы увидите** — блок с текущими настройками и сразу открытый дашборд (это подсказка, а не вопрос — агент не ждёт ответа и идёт работать):

```
Режим: полуавтомат · глубина: обычная — спрошу только то, что в задаче не определено, дальше соберу сам.
Дашборд открыл — обновляется сам.
Память проекта — AGENTS.md (+ CLAUDE.md со ссылкой). Скажи, если нужен другой.
```

## 4. Три независимые ручки

Всё, что напечатано после `/autopilot`, разбирается на четыре части: **режим**, **глубина**, **доводка** и **сам бриф** (всё, что не распознано как параметр). Дефисы не нужны, порядок слов не важен, все три параметра необязательны.

### 4.1. Режим — сколько у вас спрашивают

| Режим | Как включить | Что спрашивают |
|---|---|---|
| **full** — полный автомат | `/autopilot full`, «полный автомат», «ничего не спрашивай» | ничего; в конце — список решений, принятых за вас |
| **semi** — полуавтомат *(по умолчанию)* | ничего писать не нужно | только то, что в задаче не определено |
| **interview** — режим интервью | `/autopilot interview`, «погриль меня», «допроси», «разбери задачу со мной» | все развилки, какие есть |
| **manual** — ручной | `/autopilot manual`, «согласовывай каждый шаг» | те же вопросы **плюс** ваше «ок» на спецификацию и на список тасков |

**Почему четыре, а не три** (аргумент из кода): режим решает две разные вещи — сколько вас спрашивают о *продукте* и сколько вы утверждаете в *процессе*. `interview` — это «разбери задачу со мной по вопросам, а дальше собирай сам»; `manual` — то же самое плюс два гейта на артефакты, и больше ничем они не отличаются.

**Сколько будет вопросов.** Числа в скилле — калибровка, а не цель. В `semi` большинство брифов дают 2–8 вопросов, но **потолка нет**: на сырой бриф о маркетплейсе пятнадцать вопросов — это норма, и агент обязан один раз объяснить, почему их так много. Придуманный «для галочки» вопрос считается дефектом ровно так же, как пропущенный блокирующий.

**Режим можно менять по ходу** — «переключись в ручной» применится со следующей фазы, пройденные не переигрываются. Двусмысленность разрешается в `semi`; явное слово режима побеждает.

### 4.2. Глубина — сколько додумывают за вас

| Глубина | Как включить | Углубление требования | Новые возможности |
|---|---|---|---|
| **strict** | `/autopilot strict`, «строго по брифу», «ничего не добавляй» | только то, без чего требование не работает | **запрещены** |
| **normal** *(по умолчанию)* | ничего писать не нужно | по здравому смыслу, сколько требование заслуживает | можно — с привязкой к родителю и в пределах пропорции |
| **deep** | `/autopilot deep`, «проработай глубоко», «продумай за меня» | полный проход по всем измерениям каждого требования | поощряются, с теми же двумя ограничениями |

- **`strict` — это не «небрежно»:** ошибки и пустые состояния обрабатываются всё равно, иначе требование просто не работает. `strict` убирает только то, чего вы не просили.
- **`deep` не отменяет привязку:** каждая добавленная возможность называет своё родительское требование. `deep` покупает тщательность, а не другой проект.
- **`deep` дополнительно включает состязательный проход** — премортем по самому брифу: где разваливается сама идея, а не где недосказано требование. Он же всегда работает в `interview` и `manual` на любой глубине.

### 4.3. Доводка (`polish`) — единственная ручка, стоящая заметных денег

**По умолчанию выключена.** Включается словом `polish` или «вылижи», «доведи до идеала», «сравни с эталоном», «бюджет не важен, важен результат».

Что делает: после слепой приёмки запускает собранный проект, ставит рядом с **вашим** эталоном и ищет конкретные различия. Найденное становится обычными тасками — с ревью, тестами и отдельными коммитами.

- **Эталон — только ваш.** Сайты, на которые должно быть похоже, скриншот, текст с нужным тоном, число, которое надо побить. Агент спросит один раз в брифинге и сложит в `reference.md`.
- **Без эталона доводка не запускается** — и это главное. Критик, которому не с чем сравнивать, придумает эталон сам, и сборка честно поедет к стандарту, который никто не выбирал.
- **Три условия остановки**, срабатывает первое: круг не нашёл ничего нового, пройдено три круга, или вы сказали «хватит». «Пока критик не будет доволен» условием не является — он не будет доволен никогда.
- **Круг, который что-то сломал, откатывается целиком**, а не чинится следующим кругом.

Уместна там, где качество видно и есть с чем сравнить: интерфейсы, лендинги, тексты. Для внутренней логики со спецификацией судья и так есть — тесты.

## 5. Как устроен прогон: девять фаз

Главный принцип, сформулированный в коде: **«порядок и есть продукт»**. Код пишется в предпоследней фазе; всё до неё существует, чтобы решить, *что* строить, всё после — чтобы доказать, что построено именно это.

| # | Фаза | Пользователю | Что производит |
|---|---|---|---|
| 0 | Preflight | Подготовка | репозиторий настроен, создана `.autopilot/`, выбран файл памяти проекта |
| 1 | Manifest | Требования | `brief.md` (ваши слова дословно), `manifest.md` (R01…Rnn) |
| 2 | Briefing | Брифинг | ответы записаны в манифест |
| 3 | Spec | Спецификация | `spec.md` |
| 4 | Plan | План | `tickets/NN-*.md`, засеян `interfaces.md` |
| 5 | Subagents | Разработка | код, коммиты, растущий `interfaces.md` |
| 6 | Review | Код-ревью | ревью каждого таска |
| 7 | Instruments | *(не отдельный этап)* | `state.js`, `dashboard.html` |
| 8 | Final | Приёмка | слепая приёмка, финальный отчёт |
| 9 | Memory | *(не отдельный этап)* | `CLAUDE.md` / `AGENTS.md`, `docs/adr/` |

**Правила фаз читаются в момент старта фазы, а не заранее** — именно это держит рабочий контекст небольшим. Единица загрузки — файл, поэтому то, что нужно одной фазе и не нужно другой, вынесено в отдельный файл.

**Словарь для пользователя** (в коде на этом настаивают отдельно): «сборка» — это весь прогон, а не один этап; пятая фаза называется «Разработка». Единица работы — **«таск»**, а «задача» — это то, что поставили вы.

### Ярусы: сколько тасков будет

Ярус читается **по продукту**, а не по длине спецификации.

| Ярус | Как выглядит продукт | Тасков |
|---|---|---|
| **T0** | одна поверхность, один слой, без внешних сервисов — страница, форма, скрипт, один эндпоинт | **нет** — строится сразу из спецификации в одном контексте |
| **T1** | одна цельная фича: несколько поверхностей над одной формой данных, максимум один внешний сервис | 2–3 |
| **T2** | несколько фич или одна фича через несколько слоёв — хранилище, логика, интерфейс, интеграция | 4–8 |
| **T3** | ≥3 действительно независимых подсистемы, у каждой свои данные и своя причина меняться | 9–16 |
| **>16** | — | **не допускается**: либо обоснование строкой в спецификации, либо разбить на два прогона |

T0 — обычное дело: лендинг, форма, скрипт собираются одним проходом, и дробить их было бы расточительством.

### Как летят таски

- Каждый таск — **узкий, но полный путь через все слои**, которые он затрагивает (данные, логика, интерфейс, тесты). Когда он готов — работает что-то end-to-end, что раньше не работало.
- Таски идут **волнами**: вся волна запускается одним сообщением, по одному субагенту на таск. Два вызова в двух сообщениях выполнятся последовательно — в коде это названо «дефолтным провалом», потому что снаружи серийный полёт выглядит как правильный.
- **Потолок — три таска в воздухе одновременно.**
- **Зоны не пересекаются:** два таска, пишущие в одни файлы, всегда сериализуются — параллельная запись теряется молча.
- **Волна не барьер:** как только один таск вернулся, запускается следующий, у которого разблокированы зависимости.
- **Ничто не параллелится с таском 01** — он создаёт каркас, схему, общие примитивы.
- Таски, закрывающие ваши требования (`R`), идут раньше тасков, закрывающих добавленное агентом (`A`) — если прогон оборвётся, недостающим окажется добавленное, а не ваше.

**Стоимость, названная в самом коде:** каждая граница таска — свежий контекст, который «влетает с нуля»: читает интерфейсы, изучает код, выясняет стек и тестовую команду — **20–40 тысяч токенов чистой переориентации** до первой написанной строки, плюс контексты ревью. Отсюда правило: **меньше и плотнее тасков лучше, чем больше и тоньше**, и запрет «изобретать параллелизм» ради красивой картинки на дашборде.

## 6. Главная механика: ваша задача не теряется

Это то, ради чего скилл вообще существует. Типичная беда сборки «по описанию»: вы надиктовали бриф, дальше пошли вопросы, спецификация, таски, код — и половины из просимого на выходе нет. Не потому что отказались, а потому что на каком-то шаге оно перестало упоминаться.

Autopilot первым делом разбирает ваш текст на **пронумерованные требования** и записывает их дословно в файл. Дальше у каждого требования есть статус, и на каждой фазе стоит гейт:

| Гейт | После фазы | Условие прохода |
|---|---|---|
| **G1** | Брифинг | у каждого требования есть статус; ни одно не осталось `open` без записанной причины |
| **G2** | Спецификация | каждое живое требование — `in-spec`, `deferred` или `dropped`, ноль `open`, **и независимый читатель, которому дали только бриф и спецификацию, не находит пропаж** |
| **G3** | План | каждое `in-spec` ведёт к ≥1 таску, **и каждый таск прослеживается к ≥1 требованию** (ловит работу, которую никто не заказывал) |
| **G4** | Приёмка | слепая приёмка против брифа, спецификация изъята; любое расхождение с манифестом попадает в отчёт |

**G2 и G4 — одна и та же проверка на двух концах полёта, и нужны обе.** Обе меряют результат вашими же словами, забрав у проверяющего пересказ. Всё, что между ними, меряется спецификацией — потому что именно её получили исполнители.

**Провалившийся гейт — не предупреждение, а возврат фазы на переделку.**

**Снять требование может только пользователь**, своими словами, процитированными в манифест. Агент вправе предложить отложить — вычеркнуть не вправе. Молчание отменой не считается. Единственное, что может попасть в манифест после брифинга — строка `D##`: то, что **доказала сборка** (модель данных не держится, предполагаемый интерфейс невозможен). Идея, пришедшая по ходу, — не `D##`.

## 7. Пять правил, которые не обсуждаются

В коде явно разделено: почти всё в скилле — аргументы, и аргумент может проиграть, если следование ему ухудшит результат (но тогда это осознанное решение, названное вслух). **Пять правил не проигрывают никогда, ни в одном режиме, на любой глубине:**

1. **Требование убирает только пользователь** — своими словами, процитированными в манифест.
2. **Секрет никогда не запрашивается, не повторяется и не записывается** — ни в файл, ни в промпт, ни в коммит, ни в отчёт.
3. **Факт о пользователе не выдумывается.** Цены, тексты, адреса, аккаунты остаются видимыми заглушками, пока вы их не дадите.
4. **Необратимое или направленное вовне действие — это вопрос:** деплой, публикация, оплата, сообщение третьей стороне, удаление данных, перезапись истории git. Действует **во всех четырёх режимах, включая полный автомат.**
5. **Оркестратор не пишет код проекта.** Его клавиатура достаёт до `.autopilot/`, файла памяти и git. Всё остальное — даже правка на две строки, даже красный тест — уходит вниз субагенту.

Пятое правило объяснено отдельно и стоит того, чтобы понимать: каждая правка руками оркестратора оставляет у него дифф до конца прогона и ухудшает каждый следующий таск. «Дороже гонять субагента ради двух строк» — дороже этому таску, платят все следующие.

## 8. Работа с секретами

Отдельный раздел, связывающий все фазы:

- **Никогда не запрашивается.** Ключ, токен, пароль, строка подключения, номер карты — не вопрос. *Какой провайдер* — вопрос. *Есть ли аккаунт* — вопрос. Сам ключ — нет.
- **Редакция на входе, до записи куда-либо.** Бриф, каждый ваш ответ и каждый вставленный фрагмент проходят гейт редакции **до** попадания в файл. Найденный секрет становится `[REDACTED:<VAR_NAME>]` — имя переменной выживает, значение нет.
- **«Дословно» всегда означает «дословно после редакции».**
- **Обращение по имени:** `STRIPE_SECRET_KEY`, не значение. Значение вы кладёте в `.env` сами; `.env` попадает в `.gitignore` до первого коммита; финальный отчёт перечисляет, какие имена ещё пустые.
- **Утёкший секрет — условие остановки:** о нём сообщают немедленно, простыми словами, с советом ротировать.

## 9. Что появится у вас на диске

```
.autopilot/
├── <feature-slug>/
│   ├── <ГГГГ-ММ-ДД>-brief.md   ваши исходные слова (после редакции), больше не редактируются
│   ├── manifest.md             R01…Rnn — требования и их статусы
│   ├── reference.md            эталоны — ваши, никогда не агента
│   ├── spec.md                 спецификация
│   ├── interfaces.md           границы модулей, затем то, что построили готовые таски
│   └── tickets/NN-<slug>.md
├── README.md                   как читать эту папку — для человека
├── state.js                    состояние прогона: этапы, таски, тайминги, долг
└── dashboard.html              человеческий вид — копируется один раз, дальше сам читает state.js

CLAUDE.md | AGENTS.md           память проекта — что первым прочитает следующая сессия
docs/adr/                       решения, переживающие прогон (ярус T2+)
```

Три вещи не взаимозаменяемы: `.autopilot/` — запись **этого** прогона; файл памяти в корне — проект как он есть сейчас, для того, кто откроет репозиторий следующим; `docs/adr/` — почему он такой. Спецификация ничего не стоит на следующий день после сдачи, а рассуждения внутри неё стоят годы — поэтому то, что должно пережить прогон, выносится в ADR.

**`.autopilot/` коммитится, а не игнорируется** — это ваша запись того, что обещали и что сдали. «Прогон, не оставивший ничего под `.autopilot/`, не состоялся».

### Как выбирается файл памяти проекта

По первому совпадению сверху вниз: существует `CLAUDE.md` → он; существует `AGENTS.md` → он; существуют оба → тот, где уже есть описание проекта (иначе `AGENTS.md`, и второй файл не трогают); есть каталог `.claude/` или переменные `$CLAUDECODE`/`$CLAUDE_CODE_ENTRYPOINT` → `CLAUDE.md`; есть `.cursor/` → `AGENTS.md`; есть `.codex/` или `.github/copilot-instructions.md` → `AGENTS.md`; ничего не совпало → `AGENTS.md` плюс `CLAUDE.md` с одной строкой-ссылкой.

**Всё, что Autopilot пишет, лежит между маркерами:**

```markdown
<!-- autopilot:start -->
...
<!-- autopilot:end -->
```

Одно правило — две выгоды: обновление это «заменить то, что между маркерами», и **всё, что вы написали вне них, неприкосновенно**. Репозиторий, чей `CLAUDE.md` несёт выстраданные правила команды, обязан выйти из прогона Autopilot с этими правилами целыми. Если на повторном прогоне маркеров нет, а разделы Autopilot узнаваемо есть — их обернут, а не допишут вторую копию.

## 10. Дашборд

`.autopilot/dashboard.html` **открывается сам** в начале сборки — искать и запускать ничего не нужно. Работает офлайн, без сервера, без сборки. Раз в десять секунд подтягивает свежие цифры, не перезагружая страницу (позиция прокрутки и выделение не теряются); кнопка ⟳ это отключает. Есть переключатели темы и языка (RU/EN).

Что видно: восемь этапов цикла с отметками пройденных, текущего и пропущенных (с причиной — «ярус T0 — без разбивки на таски»); живые таймеры прогона, этапа и текущего таска; все таски сразу после нарезки плана — сколько готово, сколько в работе, сколько ждёт; параллельные таски с отдельными тикающими часами; общая шкала прогресса и доля закрытых требований брифа.

### ⚠️ Тонкость с открытием дашборда (важно на Windows)

В коде описаны два пути:

- **Path A — панель внутри окна агента** (предпочтительный). Файл нельзя отдать панели как `file://` — панель встраивает HTML в `data:`-URL, и тогда `state.js` не подгружается, а пользователь весь прогон видит экран «дашборд ещё не прочитал состояние». Поэтому каталог отдаётся по http, и поднимается сервер:
  ```bash
  PORT=$(python3 -c 'import socket; ...')
  python3 -m http.server "$PORT" --bind 127.0.0.1 --directory .autopilot &
  ```
- **Path B — системный браузер** (`open` / `xdg-open` / `start ""`), без сервера.

**Проблема:** условие переключения на Path B сформулировано как «нет панели **или нет `python3`**». На стандартной Windows `python3` в PATH **есть** — это App Execution Alias Microsoft Store, который печатает `Python` и завершается с кодом 49, ничего не исполнив. Формально «python3 есть», фактически сервер не поднимется, а `PORT` окажется пустым.

**Что делать:** если дашборд не открылся — скажите агенту «открой дашборд через системный браузер» или укажите реальный интерпретатор (на Windows это обычно `python` или `py`, например `C:\Python314\python.exe`). Проверить, чем является `python3` у вас: `python3 -V` — если печатает голое `Python` без номера версии, это заглушка.

## 11. Сколько это стоит и сколько идёт

Честная оценка на основе чисел из кода:

- **Ярус T0** (лендинг, форма, скрипт): один контекст, тасков нет, ревью один раз — самый дешёвый сценарий.
- **T1–T3:** каждый таск — отдельный контекст субагента, **20–40k токенов только на «влёт»** плюс написание кода плюс контекст ревью. Умножайте на число тасков (2–3 / 4–8 / 9–16) и добавьте фазы оркестратора.
- **`polish`** добавляет до трёх кругов, каждый из которых — снова таски с ревью и тестами. Это самая дорогая опция, и она поэтому выключена по умолчанию.
- **Экономия времени** идёт от волн: независимые таски летят параллельно (до трёх одновременно).

Ориентир: проект уровня T2 с `polish` — это заметно больше токенов, чем «просто попросить агента написать код», и в этом смысл: вы платите за спецификацию, гейты, ревью и слепую приёмку.

## 12. Подводные камни и на что смотреть

| Что | Почему важно |
|---|---|
| **Автотриггер по фразам** | Скилл срабатывает не только на `/autopilot`, но и на «собери под ключ», «build it for me», «не задавай лишних вопросов». При глобальной установке это действует во всех проектах. Если нужен контроль — ставьте без `-g` или зовите строго слэш-командой |
| **Пишет в `CLAUDE.md` / `AGENTS.md`** | Аккуратно, между маркерами, чужое не трогает — но если у вас там канон команды, лучше сразу сказать «память проекта — AGENTS.md» (агент предлагает это первой репликой) |
| **Делает `git init`** | Если репозитория нет, он создаётся в фазе 0 вместе с `.gitignore` — чтобы первый коммит мог случиться сразу. Запускать лучше в папке нового проекта |
| **`python3` для дашборда** | См. §10 — на Windows это типовая ловушка |
| **`npm install` в отчёте** | Финальный отчёт даёт команду запуска (`npm install && npm run dev`). Установка пакетов без вашей просьбы прямо названа красным флагом в коде |
| **Молодой проект** | 3 недели, один автор, MIT — для экспериментов и продуктовых сборок, не для критичной инфраструктуры |
| **Один диалог = один проект** | Идея больше одного проекта → сначала определить назначение, потом Autopilot |

**Чего скилл не делает:** не устанавливает пакеты по своей инициативе, не деплоит без вопроса, не платит, не рассылает, не удаляет данные и не переписывает историю git без явного вашего согласия — во всех режимах.

## 13. Проверка перед использованием (для осторожных)

Скилл — это инструкции, которые агент выполняет с полными правами. Разумный минимум проверки:

```bash
# что реально лежит на диске
find ~/.claude/skills/autopilot -type f | sort

# есть ли хуки (перехват событий агента) — у autopilot их нет, должно быть 0
find ~/.claude/skills/autopilot -name "hooks.json" | wc -l

# сверить с апстримом (различия только в переводе строк — норма)
curl -fsSL https://raw.githubusercontent.com/nick-vels/skills/main/skills/autopilot/SKILL.md -o /tmp/upstream.md
diff <(tr -d '\r' < ~/.claude/skills/autopilot/SKILL.md) /tmp/upstream.md
```

Autopilot состоит **только из markdown-файлов** — ни исполняемых скриптов, ни хуков, ни MCP-серверов. Всё, что он делает, делает сам агент по этим инструкциям, и все опасные действия остаются под обычными разрешениями вашего агента.
