# Дыры в инструментарии: AI-агент + Remotion-конвейер

> **Тема:** какие инструменты реально стоит подключать к проекту, где Claude Code работает с Remotion (видео из кода)
> **Автор:** Komersaint (Евгений)
> **Дата:** 2026-08-14
> **Теги:** claude-code, remotion, github-actions, ci-cd, video-as-code, плагины

## Контекст

Кейс из реального командного проекта (студия сборки видео из кода на Remotion,
несколько участников, разный уровень владения git). Повод — в чате скинули
ссылку на официальный плагин Remotion для Claude Code без объяснений, что это
и зачем. Плагин разобрали, установили, протестировали живьём — и заодно
проверили, чего в конвейере ещё не хватает. Ниже — четыре находки, которые
применимы к любому похожему проекту (AI-агент пишет код, который производит
медиа-контент).

## 1. Ревью упирается в одного человека

Если в команде один мейнтейнер, который лично ревьюит каждый PR в ядро
репозитория, а часть участников не разбирается в git — это узкое горлышко,
которое растёт вместе с командой.

**Решение:** официальный `claude-code-action` от Anthropic
(`anthropics/claude-code-action`). Что делает:
- автоматический код-ревью на каждый PR, до того как до него дойдут руки у
  мейнтейнера;
- отвечает на упоминания `@claude` прямо в комментариях issue/PR — участник,
  который не понимает git, может попросить бота помочь, не отвлекая
  мейнтейнера по мелочам.

Ставится через `/install-github-app` из Claude Code за 5 минут. Стоимость —
только токены API/подписка + минуты GitHub Actions, для команды такого
масштаба это копейки.

## 2. Нет автоматической проверки, что сборка не сломана

Часто в правилах проекта написано что-то вроде «перед мержем ядра —
запустить сборку демо-примера», но это работает только на честном слове.
Человек забыл — сломанный код уходит в main незамеченным.

**Решение:** добавить в CI шаг, который реально запускает сборку/рендер
демо-проекта на каждый PR по ядру и валит проверку, если он не проходит.
Дёшево (это просто ещё один job в существующем workflow), и не зависит от
памяти конкретного человека.

## 3. Что НЕ стоит тащить без реальной необходимости

- **Облачный рендер под нагрузкой (например, Remotion Lambda).** Решает
  проблему «нужно рендерить много и быстро». Если рендеров пока немного и
  время не критично — это трата денег на масштаб, которого ещё нет.
- **Платные SaaS-интеграции (Adobe/Canva/Cloudinary и т.п.) из официального
  маркетплейса Claude-плагинов.** Если у проекта уже есть свой бесплатный
  пайплайн ассетов (стоки, иконки, локальная генерация) — платный дубль того
  же самого не добавляет ценности.
- **Автоматизация, которая меняет осознанную границу проекта** (например,
  публикация готового контента изнутри репозитория, если команда решила, что
  репозиторий — только про технологию, а не про сами материалы). Даже если
  технически легко добавить — сначала спросить, а не тихо расширять периметр.

## 4. Индустриальный предел 2026 года — управление ожиданиями

Не существует (ни у одной команды, не только у нас) инструмента, который
умеет проверять, что видео/анимация, сгенерированная агентом, **по смыслу**
соответствует задумке. Скриншот-диффинг и метрики качества (SSIM/PSNR/VMAF)
ловят только технический дрейф от эталона — не адекватность содержания.

Практический вывод: закладывать в процесс, что финальную проверку ролика
всё равно делает человек глазами — это не недоработка своего пайплайна, а
текущая граница возможностей во всей отрасли.
